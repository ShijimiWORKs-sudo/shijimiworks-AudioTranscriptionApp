# Personal Edition 仕様書 v1.0

## 目的

「毎日の仕事・電話・打ち合わせ・会議で実際に使える」完成度を目指す。Prototypeで確認したASRパイプラインの上に、日常運用に必要な機能を積み上げる。

## 主要機能

### 1. 音声ファイル管理

登録音声ごとに以下を記録する: ファイル名 / 録音日時 / ファイルサイズ / 音声時間 / 用途 / テンプレート / 処理日時 / 処理状態 / 使用モデル。

### 2. 再処理機能

一度文字起こしした音声を「別テンプレート / 別モデル / 別言語設定 / 別話者設定」で再処理できる。音声ファイル自体の再登録は不要（音声実体とメタデータ・処理結果を分離した設計のため実現できる。§DATA_MODEL_SPEC参照）。

### 3. タイムスタンプ

```ts
interface TranscriptSegment {
  id: string;
  startMs: number;
  endMs: number;
  text: string;
  speaker?: string;
  confidence?: number;
}
```

### 4. 話者分離

pyannote.audio（またはWhisperX経由）をASR後処理として追加し、「話者A/B/C」の仮ラベルで検出する。ユーザーが「話者A→自分」「話者B→田中さん」のように後から名前を割り当てられるようにする。自動で個人を断定はしない（指示書§31「AIが勝手に事実を作らない」方針）。

### 5. 文字起こし編集

タイムスタンプ・話者・文章の単位で編集できるUI（単なるtextareaではない）。各セグメントに「話者変更」「編集」「削除」を提供。

### 6. 音声と文字の同期

音声プレイヤーと文字起こしを連動させる。文字クリックでその時刻から再生、再生位置に応じて該当テキストをハイライトする。

### 7. 出力形式

最低限 TXT / Markdown / JSON。可能ならDOCX / PDF / CSVも追加。議事録の場合はタイトル・日時・参加者・要約・決定事項・TODOを整形して出力する。

### 8. 履歴管理

検索条件: 日付 / 用途 / ファイル名 / テンプレート / 話者 / キーワード。

### 9. ローカルDB

SQLiteを利用し、メタデータと文字起こし結果を保存する。音声ファイル実体はユーザー指定のローカル保存場所に置き、DBと分離する。

### 10. プライバシー / オフライン動作

- 既定では音声データはPC内部→ローカルASR→PC内部のみで完結する。
- ユーザーの明示的操作なしに音声アップロード・クラウド保存・外部API送信・外部AIへの送信を行わない。
- インターネット接続が必要なのは「モデル初回ダウンロード」「テンプレート取得」「アプリ更新」のみに限定する。

### 11. モデル管理画面

設定 → AIモデル。インストール済みモデルの一覧（容量・日本語対応・CPU/GPU要否）、モデル追加・削除、使用モデルの切り替え。ASR Engineの交換可能設計（`docs/architecture` §3）に基づく。

### 12. AIによる要約（将来拡張、Phase 10以降）

- ASR（音声→文字）とLLM（文字→要約・構造化）は別モデルとして分離する。
- クラウドAIに依存せず、まず文字起こしと構造化を完成させ、その後ローカルLLMを追加可能な設計にする。
- 音声に存在しない情報（日時・参加者・決定事項・期限・担当者等）を勝手に生成しない。不明な情報は `[不明]`、推定した場合は `[推定]` と明示する。

### 13. セキュリティ

パストラバーサル防止 / 不正なテンプレートJSON対策 / 外部URL取得時の安全性 / 巨大ファイル対策 / 不正なファイル形式 / SQLite破損対策 / 自動バックアップ / ロックファイル / 一時ファイル削除。

### 14. バックアップ

設定 → バックアップ。対象: DB / テンプレート / 設定 / 文字起こし履歴。音声ファイルは容量が大きいため既定では対象外とする。

## UI方針

業務ソフトのような無機質なUIにはしないが、派手にもしない。「音声ファイル→用途選択→テンプレート選択→文字起こし→確認→出力」の流れを迷わず操作できることを最優先する。

## 完成条件（最終目標）

インターネット接続が無くても、既にモデルをダウンロード済みであれば文字起こしできること。Windowsデスクトップアプリ（EXE）として直接起動できること。
